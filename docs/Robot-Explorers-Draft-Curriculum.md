# Robot Explorers: Edison Robot Curriculum Guide

**Grades 2–4 | Six Classes | Eight Sessions Each | 1 Hour Per Session**

---

## At a Glance

**Class 1 — Grade 2, Semester 1: "Meet the Robots"**
Students explore what Edison can do using pre-set barcodes — no programming required. All activities are game-based and accessible to complete beginners.

- Session 1: Robot anatomy, sensors, and the input→process→output concept using Human Robot activity
- Session 2: Clap-controlled driving and racing after a Clap Sensor Game warm-up
- Session 3: Obstacle avoidance barcode, building obstacle fields, introduced by Obstacle Avoidance Rule activity
- Session 4: Ball game introduction — drive Edison to pick up and deliver a ball using clap control
- Session 5: Ball game tournament with strategy iteration between rounds
- Session 6: Line tracking and sumo wrestling, introduced by Human Line Follower activity
- Session 7: Bounce-in-borders challenge with student-built custom arenas
- Session 8: Engineering showcase — teams build a challenge for another team and present their work

---

**Class 2 — Grade 2, Semester 2: "Program the Robot"**
Students write their first programs using physical Card Coding cards — no computer needed. The Blind Maze Walker and Two-Wheel Robot activities anchor the key concepts before students touch the cards.

- Session 1: Barcode warm-up accessible to new students; returning students compete in ball game
- Session 2: Sequencing with Card Coding Lesson 1, introduced by Blind Maze Walker activity
- Session 3: Loops and repeats with Card Coding Lesson 2, introduced by Human Loop activity
- Session 4: Simple maze engineering challenge, introduced by Two-Wheel Robot (straight + turn) to explain why turns fail
- Session 5: Sensors and wait-until with Card Coding Lesson 3, revisiting Clap Sensor Game
- Session 6: Ball game with a Card Coding programmed approach — compare programmed vs. manual control
- Session 7: Open design challenge using all Card Coding concepts
- Session 8: Team showcase and preview of app-based programming

---

**Class 3 — Grade 3, Semester 1: "Block Builders"**
Students move to EdBlocks app programming on iPads or Chromebooks, learning to drive precisely, calibrate turns, and navigate a maze. Remote-first planning is introduced here.

- Session 1: Full barcode reset — accessible to new students, returning students coach
- Session 2: Clap racing and sumo games using EdBlocks barcode activities
- Session 3: EdBlocks environment — connect Edison, download a program, deliberately break it and fix it
- Session 4: Drive distance programming and measurement, introduced by Two-Wheel Robot drift activity
- Session 5: Turn calibration — each Edison is different, introduced by Two-Wheel Robot turning activity
- Session 6: Maze navigation using remote-first planning — drive it, document it, then program it
- Session 7: Teams build mazes for each other and program Edison to solve them
- Session 8: Ball game with a programmed EdBlocks approach run

---

**Class 4 — Grade 3, Semester 2: "Sensor Squad"**
Students write programs that react to the world — line following, obstacle detection, lights, and sound. Three physical activities (PL-7, PL-9, PL-10) directly explain sensor behavior before students program it.

- Session 1: Barcode and EdBlocks warm-up; new students paired with returning mentors
- Session 2: Line following program, introduced by Human Line Following with Sound Cues to explain oscillation
- Session 3: Stop-at-a-line programs, introduced by Delay and Reaction Time activity to explain overshoot
- Session 4: Lights and sound output — robot greeting and morse-code light challenge
- Session 5: Obstacle detection and avoidance programs, introduced by Obstacle Avoidance Rule activity
- Session 6: Programmed stay-in-borders behavior; sumo tournament with sensor programs
- Session 7: Music and performance — robot talent show combining lights, sound, and motion
- Session 8: Grand challenge mission combining multiple sensors and outputs

---

**Class 5 — Grade 4, Semester 1: "Challenge Engineers"**
Students work through EdBlocks at a faster pace and face open-ended challenges with no step-by-step guidance. Advanced students get their first look at EdScratch.

- Session 1: Ball game entry for all; returning students program the approach from memory
- Session 2: EdBlocks fast-track for new students; returning students build complex mazes
- Session 3: Advanced 5-turn maze using remote-first planning and systematic debugging
- Session 4: Teams design sensor challenge courses for each other to program
- Session 5: Robot Olympics Event 1 — line following race on a shared figure-8 track
- Session 6: Robot Olympics Event 2 — teams design and swap obstacle mazes
- Session 7: EdScratch Units 1–2 for advanced students; EdBlocks capstone for others
- Session 8: Operation Neko Prime — scenario-based collaboration challenge with no prescribed solution

---

**Class 6 — Grade 4, Semester 2: "Robot Masters"**
Students tackle open-ended design challenges using EdBlocks (advanced) or EdScratch, culminating in a student-designed capstone project presented to the group.

- Session 1: Warm-up and placement — returning students open EdScratch, new students start with barcodes
- Session 2: EdScratch Move It (driving and outputs) alongside EdBlocks sensor activities
- Session 3: Loops and geometry — program rectangles and shapes, compare square-making to the Human Loop activity
- Session 4: Quad Squad geometry challenge — program all four quadrilateral types using calculated turn angles
- Session 5: Conditionals and line algorithms — traffic light intersection challenge
- Session 6: Course design challenge — teams write requirements, swap, and program each other's courses
- Session 7: Capstone project work — problem statement presentations, two documented iterations required
- Session 8: Capstone showcase — 3-minute presentations with demo, peer questions, and class vote

## Design Principles

**Engineering process, every class.** The through-line across all six classes is a four-step loop students internalize over time: *Understand → Imagine → Build → Prove.* Sessions are designed so that loop appears naturally in the activity — kids are iterating without being told they're doing engineering.

**Fun first.** Each class opens with something immediately playable. The ball game, sumo wrestling, and clap-controlled racing are genuinely engaging. Programming complexity increases, but the reward (a robot doing something cool) must be visible every session.

**Multiple entry points.** Every class is designed so a student who missed the previous class — or is starting the grade fresh — can participate from session one. Returning students go deeper; new students still succeed. Session 1 of each class is always barcode-based, which requires zero prior knowledge.

**Controlled overlap.** The first session of each semester intentionally revisits skills from the previous semester. This is not redundancy — it's retrieval practice for returning students and an accessible entry point for new ones.

**Remote-first planning.** When students face a new challenge — a maze, a delivery task, a course — have them drive it manually with the remote control first. This gives them a concrete experience of what the robot needs to do before they write a single line of code. After the manual run, they document the steps on paper as a sequence: *drive forward to the corner, turn right, drive to the ball, stop.* That paper list becomes the first draft of their program. This approach bridges physical intuition and abstract programming, gives students something concrete to translate rather than a blank screen to stare at, and surfaces the hard parts of the task before the coding even starts. Use this technique whenever introducing a new challenge type in Classes 3–6.

## Equipment Notes

- **Ball game catch:** Edison's front catch holds a small ball; a fixed goal catch grips harder and holds the ball when Edison drops it off. Works with any pre-set driving mode.
- **Mazes:** Use foam noodles, tape, or cardboard strips. Edison doesn't turn exactly 90° — this is a feature, not a bug. Iteration to nail turns is the engineering lesson.
- **Barcodes:** Print the complete barcode list. Laminate. Keep a set at every table.
- **EdMat:** Print at tabloid/A3 or tile two letter sheets. Laminate.
- **Devices:** EdBlocks runs in Chrome, Edge, or Opera. iPads and Chromebooks both work. Confirm USB connectivity before first coding session.

## Physical Learning Activities

These are offline, embodied activities — no robot required. Each one makes an abstract programming or engineering concept physical and memorable before students encounter it on the robot. They work best as a 5–10 minute opener immediately before the related robot activity, so the connection is immediate.

For grades 2–3, plan on using at least two of these per class. They are not optional extras — they are the primary explanation for several concepts that are otherwise hard to see.

---

### PL-1: Human Robot
**Concept:** Sequencing, precision, input → process → output
**Time:** 5–8 minutes
**Setup:** Open floor space, optional tape line or simple obstacle

One student is the robot — arms at sides, moves only when instructed. One or two students are the programmers and may only give these commands: *step forward, step backward, turn left, turn right, stop.* The robot follows instructions literally — no interpreting, no guessing intent. Walk the robot through a simple taped path or around a chair.

Discovery: "turn left" without a count means the robot doesn't know when to stop turning. "step forward" without a number means the robot doesn't know how many steps. Programmers quickly learn they have to be far more specific than feels natural.

**Used in:** Class 1 Session 1, Class 2 Session 2

---

### PL-2: Blind Maze Walker
**Concept:** Sequencing, debugging, precise instruction
**Time:** 10–15 minutes
**Setup:** Tape a path on the floor — straight section, one or two turns, a finish line. Width should be about one large step.

One student is blindfolded and must stay on the tape path using only verbal instructions from their partner: *step forward, step forward, turn left, step forward.* If the blindfolded student steps off the tape, that's a bug — stop, figure out which instruction was wrong, fix it, restart from where they went off.

Rotate so multiple students get to be both the robot and the programmer. The blindfolded student must follow instructions as given, not as intended.

**Used in:** Class 2 Session 2, Class 3 Session 6

---

### PL-3: Two-Wheel Robot — Straight Line
**Concept:** Why Edison drifts; mechanical imperfection; what calibration fixes
**Time:** 5–8 minutes
**Setup:** Open floor, tape a straight 4–5 meter line

Two students stand side by side and hold hands — they are the two drive wheels. Both close their eyes. A third student calls commands: *both step forward* (repeated several times). The goal is to follow the tape line.

They won't. Slight differences in step size between the two students cause the pair to curve left or right. This is exactly what happens inside Edison: the two motors don't spin at precisely the same speed.

Debrief: "What would you have to do to go straight?" The shorter-stepping wheel needs bigger steps, or the longer-stepping one needs smaller steps — this is what drive calibration does.

**Used in:** Class 2 Session 4, Class 3 Session 4

---

### PL-4: Two-Wheel Robot — Turning
**Concept:** Why robot turns aren't exactly 90°; what a robot turn physically is
**Time:** 5–8 minutes
**Setup:** Open floor; tape a cross or right-angle marks for reference

Same two-students-as-wheels setup. To turn right: the right-side student (right wheel) stays in place and pivots on the spot; the left-side student (left wheel) steps forward while the right pivots. Where do they end up? Measure the angle with a protractor — it won't be exactly 90° because human steps aren't uniform in size.

Try different numbers of steps for the left wheel until you get close to 90°. Try it again — same result? (Probably slightly different each time.) This is why every Edison has its own calibration value, and why the degree number in EdBlocks that works for one robot won't work for another.

**Used in:** Class 2 Session 4, Class 3 Session 5

---

### PL-5: Clap Sensor Game
**Concept:** Event-driven behavior; sensors trigger actions, not timers
**Time:** 5 minutes
**Setup:** None

Establish rules with the class: one clap = take one step forward; two claps = turn right 90°; three claps = turn left 90°; no sound = freeze. Practice each once together.

Teacher claps a sequence; students respond. Then try navigating one student from one side of the room to the other using only claps. Other students predict what the "robot" will do before it moves.

Extension: two students follow different clap rules — same claps, different behavior. This shows how the program (not the sensor) determines the response.

**Used in:** Class 1 Session 2, Class 2 Session 5

---

### PL-6: Obstacle Avoidance Rule
**Concept:** Fixed-rule conditional behavior; limits of simple rules
**Time:** 5–8 minutes
**Setup:** Open floor space; students spread out as stationary obstacles

Students walk slowly around the room. The rule: if someone is directly in front of you (within arm's length), turn right 90° and keep walking. Always right, no exceptions.

Let it run for 2 minutes. Some students will get stuck in corners or loop back on themselves. Others will move through freely.

Debrief: "What's the problem with always turning right? When does that rule fail?" This directly mirrors Edison's obstacle avoidance behavior and its corner-trap failure mode.

**Used in:** Class 1 Session 3, Class 4 Session 5

---

### PL-7: Human Line Follower
**Concept:** How a line sensor works; rule-based continuous correction
**Time:** 5–8 minutes
**Setup:** Tape a winding path on the floor, wide enough for one foot

The rule: keep the tape under your left foot at all times. If you feel tape, you're on track. If you don't feel it, shuffle left until you do. Walk slowly forward while applying the rule.

Try a straight section, then curves, then a sharp angle. Sharp angles cause students to overshoot — they swing wide before correcting back. This is exactly what Edison does and why tight turns break line following.

Debrief: "What would make this easier to follow? What would break it completely?"

**Used in:** Class 1 Session 6, Class 4 Session 2

---

### PL-8: Human Loop
**Concept:** Loops, repeat count, relationship between loop count and result
**Time:** 5 minutes
**Setup:** Open floor

Define a simple sequence: step forward twice, turn right 90°. Do it once — where are you? Now loop it 4 times. Where should you end up? (Back at start, having traced a square.) Does it work?

It usually doesn't make a perfect square, which is the point: even a correct loop produces errors when execution isn't precise. Then ask: "How many 'step forward' repeats would it take to cross the room?" Estimate, then test. This is the same problem as figuring out the distance parameter in EdBlocks.

**Used in:** Class 2 Session 3, Class 3 Session 4

---

### PL-9: Delay and Reaction Time
**Concept:** Sensor delay; why robots overshoot a line or a stop point
**Time:** 8–10 minutes
**Setup:** Tape a line across the floor. Student starts 4–5 meters away. One helper stands at the line holding a bell or clicker.

The blindfolded student walks at a normal pace toward the tape line. The helper rings the bell the moment the student's foot crosses the line. The student stops as fast as they can. Measure how far past the line they stopped.

Run it several times — vary the walking speed. Faster walking = more overshoot. Ask: if you knew the bell was coming, could you stop sooner? What if the bell rang a little bit before the line instead of on it?

This is exactly what Edison does when stopping at a black line: the sensor detects the line, sends a signal, the processor handles it, the motor gets the stop command — all of which takes time. At speed, Edison crosses the line before the stop completes. Slowing down before the line, or triggering the stop slightly early, is how you compensate.

**Used in:** Class 4 Session 3

---

### PL-10: Human Line Following with Sound Cues
**Concept:** How a line sensor actually works; oscillation as the natural result of correction
**Time:** 10–12 minutes
**Setup:** Tape a single line down the center of an open area, long enough for 8–10 steps. Two helpers stand alongside the blindfolded walker, one on each side of the line — each holding a different noisemaker (e.g., high-pitch clicker on the right, low-pitch clicker or bell on the left).

Rules: the blindfolded student walks forward continuously. Helpers watch which side of the line the student drifts to. When the student crosses to the right of the line, the right-side helper makes their sound → student turns slightly left. When the student crosses to the left of the line, the left-side helper makes their sound → student turns slightly right. Helpers only signal when the student has actually crossed to their side.

The student will weave back and forth across the line — crossing left, correcting right, crossing right, correcting left. This oscillation is not a mistake; it is exactly how Edison's line sensor works. The sensor only knows "I see black" or "I don't see black" — it cannot detect being centered. All it can do is correct when it detects it has crossed over.

Run it once at slow walk, once at faster walk. At faster speed the weaving gets wider. Debrief: "What would happen if the helpers waited longer before signaling?" (Bigger oscillations.) "What if they signaled the instant before the student crossed the line?" (Tighter path.)

**Used in:** Class 4 Session 2

## Class 1 — Grade 2, Semester 1: "Meet the Robots"

**Goal:** Students discover what Edison can do using pre-set barcodes. No programming required. Focus is exploration, play, and first encounter with the engineering loop (try → observe → improve).

**Who's in the room:** All new. No prior experience assumed.

**Programming level:** Level 0 (barcodes only)

**Key activities:** Ball game, clap racing, sumo

---

### Session 1 — What's a Robot?

**Opening concept:** Input → Process → Output. Edison as a machine that takes in information (sensors), does something (program), and acts (motors, lights, sound).

**Physical activity:** PL-1 (Human Robot) — run this before touching Edison. One student is the robot, one gives instructions. Debrief: what happened when instructions were vague? That's the same problem we'll see all semester.

**Activity:**
- Walk through Edison's parts using the Meet Edison worksheet (EdBlocks Activity 1 sheets)
- Find every sensor on the physical robot: sound, infrared, line, light
- Scan one barcode together as a class: clap-controlled driving
- Students explore: can you make Edison move without touching it?

**Engineering connection:** Understand — what does Edison need to know to do its job?

**Materials:** EdBlocks Activity 1 student sheet, complete barcode list, EdMat

---

### Session 2 — Clap Racing

**Opening concept:** A program is a set of instructions. The barcode is a tiny program already written for us.

**Physical activity:** PL-5 (Clap Sensor Game) — run for 3–4 minutes before introducing the barcode. Students already know the clap language by the time they scan it into Edison.

**Activity:**
- Students scan the clap-control barcode (pre-set program)
- Clap once = turn right. Clap twice = drive forward. Practice controlling Edison precisely.
- Set up a simple race track with tape or EdMat. Two Edisons race.
- Challenge: can you navigate the track in fewer claps?

**Engineering connection:** Understand + Imagine — what would you change about the track to make the race more interesting?

**Materials:** EdMat or tape track, complete barcode list

---

### Session 3 — Obstacle Avoidance

**Opening concept:** Sensors let robots react to the world automatically.

**Physical activity:** PL-6 (Obstacle Avoidance Rule) — students walk the room with the "always turn right" rule. After 2 minutes, debrief the corner-trap problem. Then scan the barcode and watch Edison hit the same failure mode.

**Activity:**
- Scan the obstacle avoidance barcode. Edison detects and turns away from objects automatically.
- Build a simple obstacle field with blocks or cups. Watch Edison navigate it.
- Students predict: what will Edison do next? (computational thinking — trace the logic)
- Challenge: can you make an obstacle field Edison can't escape from?

**Engineering connection:** Understand + Imagine — how do you trap it, or help it escape?

**Materials:** Cups/blocks for obstacles, complete barcode list

---

### Session 4 — Ball Game Introduction

**Opening concept:** A tool is only useful if you can control it precisely.

**Activity:**
- Introduce the ball game setup: Edison's front catch, the fixed goal catch, the ball
- Using clap-control barcode, students try to drive Edison to the ball and push/carry it to the goal
- Teams of two: one navigates, one watches and gives advice
- Scoring: one point per successful delivery

**Engineering connection:** Understand — what's hard about this? Imagine — what would make it easier?

**Materials:** Ball game catch setup, balls, goal catch, complete barcode list

---

### Session 5 — Ball Game Tournament

**Opening concept:** Improvement comes from trying, watching, and adjusting.

**Activity:**
- Round-robin tournament: 3-minute matches, count deliveries
- Between rounds, each team gets 2 minutes to practice and adjust their strategy
- Debrief: what changed between your first round and your last? Why?

**Engineering connection:** Full loop — Understand → Imagine → Build → Prove. Students articulate what they tried, what worked, what they changed.

**Materials:** Ball game setup, timer

---

### Session 6 — Line Tracking and Sumo

**Opening concept:** Robots can follow rules they never had to be taught, if we program those rules in.

**Physical activity:** PL-7 (Human Line Follower) — tape a winding path, students follow the "keep tape under left foot" rule. Walk a curve, then a sharp angle. Notice the overshoot on sharp corners. Then scan the Edison line-tracking barcode and look for the same behavior.

**Activity:**
- Scan the line-tracking barcode. Watch Edison follow a black line.
- Draw different line patterns (curves, sharp angles) and test them. Does Edison handle all shapes the same?
- Sumo: scan sumo barcode. Two Edisons on a circular EdMat. Last one in the circle wins.
- Tournament: 3 rounds of sumo

**Engineering connection:** What makes a good sumo robot? Is it something we can change? (Edison's programming is fixed here — this is a setup/strategy problem)

**Materials:** Black tape or line track mat, EdMat, complete barcode list

---

### Session 7 — Bounce in Borders

**Opening concept:** Rules can keep a robot safe inside a defined space.

**Activity:**
- Scan the bounce-in-borders barcode. Edison detects the border line and bounces away.
- Build custom arenas with black tape on a large sheet of paper. Different shapes — square, L-shape, circle.
- Challenge: which arena shape is hardest for Edison to stay inside? Which is easiest?
- Two arenas racing: time how long each robot stays in bounds

**Engineering connection:** Why does shape matter? What would you change about Edison's bounce behavior if you could?

**Materials:** Large paper sheets or tabloid, thick black tape, ruler, barcode list

---

### Session 8 — Engineering Showcase

**Opening concept:** Engineers show their work and explain their thinking.

**Activity:**
- Each pair/team builds a mini-challenge for another team using what they've learned: a race, a delivery task, or a custom arena
- Teams run each other's challenges
- Whole-group debrief: what was your favorite discovery? What would you want Edison to be able to do that it can't?
- Quick preview: "Next semester we're going to tell Edison exactly what to do, step by step."

**Engineering connection:** Presenting solutions to an audience, giving and receiving feedback

**Materials:** Whatever teams want to bring from prior sessions

## Class 2 — Grade 2, Semester 2: "Program the Robot"

**Goal:** Students write their first programs using Card Coding — physical barcode cards laid out in sequence, then scanned one by one. No computer needed. Focus is sequencing, loops, and the engineering loop applied to programming.

**Who's in the room:** Mix of returning Class 1 students and some new. Session 1 is accessible to all.

**Programming level:** Level 1 (Card Coding), with Level 0 for Session 1

**Key activities:** Card-programmed sequences, simple maze, ball game with programmed approach

**Edison Card Coding reference:** `curriculum/CardCoding/CardCoding-teachers-guide.pdf`

---

### Session 1 — Robot Warm-Up

**Activity:**
- For returning students: ball game tournament, two rounds (immediate engagement)
- For new students: quick robot intro using barcode list — clap control and obstacle avoidance
- Whole group: obstacle avoidance challenge — who can build the trickiest obstacle field?
- Introduce Card Coding: "What if instead of a program already built in, you put the program together yourself?"

**Materials:** Complete barcode list, EdMat, ball game setup, Card Coding card set

---

### Session 2 — My First Program (Card Coding Lesson 1)

**Opening concept:** A program is a sequence. Order matters.

**Physical activity:** PL-2 (Blind Maze Walker) — tape a simple path on the floor. One student blindfolded, one giving directions. Run two or three rotations. When they step off the tape, find the wrong instruction and fix it. Then introduce Card Coding as the same idea, but the cards are the instructions and Edison is the blindfolded walker.

**Activity:**
- Card Coding Lesson 1: what is a program, what is sequence
- Students build a simple drive-forward-then-backward program from cards
- Scan into Edison, run, observe
- Change the order: what happens?
- Challenge: program Edison to draw a rough square (forward, turn, forward, turn...). Does it work?

**Engineering connection:** Prove — it didn't make a square. Understand why, then Imagine what to change.

**Materials:** Card Coding student cards, EdMat

---

### Session 3 — Loops and Repeats (Card Coding Lesson 2)

**Opening concept:** When you need to do the same thing many times, write it once and repeat it.

**Physical activity:** PL-8 (Human Loop) — define the sequence: two steps forward, turn right. Ask: if we do this 4 times, where should we end up? Try it. Count the steps. Then ask how many repeats of "step forward" it would take to cross the room — estimate, test, adjust. Introduce loop cards as writing that same idea on paper.

**Activity:**
- Card Coding Lesson 2: introduce loop cards
- Compare: a program that drives forward 4 times written out vs. one that uses a loop. Same result, fewer cards.
- Challenge: program Edison to spin in a circle using a loop. Count how many repeats make a full circle.
- Pairs compete: most complete circles in 30 seconds using clap-drive hybrid

**Engineering connection:** Understand + Prove — how many repeats do you need? How did you figure that out?

**Materials:** Card Coding student cards, timer

---

### Session 4 — Simple Maze (Engineering Focus)

**Opening concept:** Engineers test, find what breaks, and fix it.

**Physical activity:** PL-3 + PL-4 (Two-Wheel Robot) — run both versions back to back. First: two students hold hands and try to walk a straight tape line with eyes closed. They'll drift. Then: try to make a 90° turn using one wheel pivoting, the other stepping. Measure the angle. Debrief: "This is what's happening inside Edison. The two wheels aren't identical, so turns and straight lines are never perfect. That's why our maze program will need fixing." Then go build and run the maze program.

**Activity:**
- Build a simple L-shaped or T-shaped maze from foam noodles or cardboard strips (1–2 turns only)
- Teams write a Card Coding program to navigate Edison from start to exit
- Expect failure — Edison's turns won't be exact. Celebrate finding the bug.
- Iterate: adjust the turn card, try again. How many tries did it take?

**Engineering connection:** Full loop — Understand (Edison missed the turn) → Imagine (adjust the turn card) → Build (swap the card and scan) → Prove (did it work?)

**Materials:** Foam noodles or cardboard strips for maze, Card Coding cards, tape for start/finish

---

### Session 5 — Sensors and Wait Until (Card Coding Lesson 3)

**Opening concept:** Sensors let programs react instead of just following a script.

**Physical activity:** PL-5 (Clap Sensor Game) — revisit briefly (2–3 minutes). This time emphasize: the student doesn't move until a clap happens. They could wait forever. That's "wait until" — the program is paused, not stopped. Then show the Card Coding "wait until clap" card.

**Activity:**
- Card Coding Lesson 3: drive forever + wait until clap
- Students build a program: Edison waits, then responds to a clap
- Game: Simon Says with Edison — the room gives claps, teams try to predict what their Edison will do
- Challenge: program a "stop light" — Edison drives until it hears a clap, stops, waits, drives again

**Engineering connection:** Input → Process → Output revisited now with student-written programs

**Materials:** Card Coding student cards, quiet-ish room for sound sensor sensitivity

---

### Session 6 — Ball Game with a Programmed Approach

**Opening concept:** Can programming help you do better at the game?

**Activity:**
- Ball game setup, but now students write a Card Coding program for the approach run
- Challenge: program Edison to drive to the ball position from the start zone automatically (no clapping), then switch to clap control to nudge it to the goal
- This requires combining pre-set barcodes with Card Coding in sequence (scan approach program, then scan clap-control barcode)
- Score: compare programmed approach vs. pure clap control — which is more consistent?

**Engineering connection:** Imagine — solutions can be combined. Understand what a good approach run needs before building it.

**Materials:** Ball game setup, Card Coding cards, barcode list

---

### Session 7 — Card Coding Project (Card Coding Lesson 5)

**Opening concept:** Engineers design for a goal, not just to make something move.

**Activity:**
- Card Coding Lesson 5: open-ended design challenge
- Each team picks a task: navigate a maze, perform a dance, play a simple game with another Edison
- Plan → program → run → present
- 10-minute design phase, 15-minute build/test phase, 10-minute sharing

**Engineering connection:** Full cycle with student-chosen goals. Understand must come first — what does success look like before you start building?

**Materials:** Card Coding cards, optional: tape for custom courses

---

### Session 8 — Showcase and What's Next

**Activity:**
- Teams run their Session 7 projects for each other and explain their thinking
- Debrief: what did you learn this semester that you didn't know at the start?
- Preview: "Next year we're going to use an app to write programs — you'll be able to do things cards can't do."

**Materials:** Projects from Session 7

## Class 3 — Grade 3, Semester 1: "Block Builders"

**Goal:** Students make the jump to app-based programming using EdBlocks. They consolidate barcode knowledge quickly (accessible to new students) and spend the bulk of the class learning to drive precisely, turn, and navigate a maze.

**Who's in the room:** Mix of returning students (from Class 2 or not), some brand new to grade 3. Session 1 is designed as a full reset.

**Programming level:** Level 0 → Level 2 → Level 3 (EdBlocks Activities 1–12)

**Key activities:** EdBlocks environment, drive + turn programming, maze engineering challenge

**Device requirement starts Session 4.** Confirm Chromebooks/iPads with Chrome/Edge and USB cables before then.

---

### Session 1 — Robot Boot Camp

**Activity:**
- Full barcode tour for the group: clap control, obstacle avoidance, sumo, bounce in borders
- Accessible to complete newcomers; returning students play coach
- Ball game: teams of two, three rounds, returning students use programmed approach from memory if they can
- Close: "This semester we're going to write programs on the computer that do things no barcode can do."

**Materials:** Complete barcode list, EdMat, ball game setup

### Session 2 — Clap Racing and Sensor Games

**Opening concept:** What Edison can sense determines what it can do.

**Activity:**
- EdBlocks Activities 2–3: clap control (student sheet), then obstacle avoidance
- Race setup: clap race on EdMat track. Best time wins.
- Sumo tournament with the sumo barcode (Activity 7)
- Debrief: what would you change about the obstacle avoidance if you could reprogram it?

**Materials:** EdMat, barcode list, EdBlocks student activity sheets 2–3, 7

---

### Session 3 — Welcome to EdBlocks

**Opening concept:** Block coding is writing instructions without typing words.

**Activity:**
- EdBlocks Activities 8–9: intro to EdBlocks environment, connect Edison to device, download first program
- Students run the example program — watch it work, then deliberately break it (delete a block) and see what happens
- Challenge: modify the example program to do something slightly different. Add a block. Remove one. Predict before running.

**Possible tech issues:** Have a troubleshooting sheet ready. USB connection is the most common issue.

**Materials:** Devices (Chrome/Edge), USB cables, EdBlocks student activity sheets 8–9

---

### Session 4 — Let's Drive

**Opening concept:** Precise movement requires knowing how far your robot actually goes.

**Physical activity:** PL-3 (Two-Wheel Robot — Straight Line) — quick version, 5 minutes. Two students hold hands, walk "forward" with eyes closed. Watch them drift. Debrief: "Before we tell Edison to drive 30 cm, let's see if it actually goes 30 cm." Then go measure.

**Activity:**
- EdBlocks Activity 10: drive blocks, distance parameters
- Students program Edison to drive exactly 30 cm. Measure with a ruler. Did it? Adjust.
- Engineering loop: measure → adjust parameter → measure again
- Challenge: program Edison to drive a rectangle. All sides equal.

**Engineering connection:** Understand (what distance?) → Imagine (what parameter value?) → Build (program it) → Prove (measure it)

**Materials:** Devices, USB cables, rulers, tape for marking distances

---

### Session 5 — Let's Turn

**Opening concept:** Turning is harder than it looks because robots aren't perfect.

**Physical activity:** PL-4 (Two-Wheel Robot — Turning) — tape a right-angle reference on the floor. Two students hold hands, try to turn 90° using one wheel pivoting and the other stepping. Measure. Adjust the step count. Try to get close to 90° — notice it varies each attempt. Debrief: "That's exactly why we have to find the right degree value for *our* Edison, and why it won't be the same as another team's."

**Activity:**
- EdBlocks Activity 11: turn blocks, degrees
- Students try to program a 90° right turn. Run it. Is it actually 90°? Probably not.
- Iterate: adjust degrees until it's as close as possible. Record what value works for their specific Edison.
- Challenge: program a square (drive + turn × 4). Does it close back on itself?

**Engineering connection:** Every Edison is slightly different. Calibration is part of the engineering process. There's no single right answer — just your robot's answer.

**Materials:** Devices, USB cables, protractor or angle guide printed on paper, tape

---

### Session 6 — Let's Try a Maze

**Opening concept:** A complex problem is just a set of simple problems in sequence.

**Activity:**
- EdBlocks Activity 12: multi-step programs, maze navigation
- Teacher-built maze: 3 turns, one dead end (foam noodles or cardboard)
- Remote-first: before opening EdBlocks, each team drives Edison through the maze using the remote control. While doing it, one partner calls out the steps aloud ("forward, forward, turn right, forward...") and the other writes them down. That list is the first draft of the program.
- Students then translate their paper list into EdBlocks blocks, run it, and compare to their manual drive
- Run → observe where Edison goes wrong → adjust one block → run again
- Emphasize: changing one thing at a time makes it easier to figure out what helped

**Engineering connection:** Debugging is engineering. Finding the exact block that's wrong is a skill.

**Materials:** Devices, USB cables, foam noodle maze, paper for mapping

---

### Session 7 — Maze Challenge

**Opening concept:** Harder problems need more iteration, not more guessing.

**Activity:**
- Students build their own mazes for another team (constraints: at least 3 turns, must have a start and finish marker)
- Teams swap mazes and program Edison to navigate the new maze
- Scoring: fastest time to complete the maze successfully wins
- If a team finishes fast, they try their maze blindfolded (one person reads the program aloud, other navigates mentally)

**Engineering connection:** Designing a challenge for someone else requires understanding the problem deeply

**Materials:** Devices, USB cables, maze-building materials, timer

---

### Session 8 — Ball Game with EdBlocks

**Opening concept:** A program can handle the boring part so you can focus on the hard part.

**Activity:**
- Ball game setup — but now students write an EdBlocks program for the approach run (drive precisely to ball pickup position from start zone)
- Once in position, switch to a pre-set barcode (clap control or obstacle avoidance) for the delivery run
- Competition: how many deliveries in 5 minutes?
- Debrief: how did programming the approach change your performance?

**Engineering connection:** Automation handles repeatable steps; human control handles variable ones

**Materials:** Ball game setup, devices, USB cables, barcode list

## Class 4 — Grade 3, Semester 2: "Sensor Squad"

**Goal:** Students go beyond driving and turning to use Edison's sensors in their programs — line following, obstacle detection, lights, and sound. Programs become reactive, not just sequential.

**Who's in the room:** Mix of returning Class 3 students and new students. Session 1 resets with barcodes.

**Programming level:** Level 3–4 (EdBlocks Activities 13–21)

**Key activities:** Line-following races, sensor obstacle courses, performance programming, border challenge

---

### Session 1 — Warm-Up and Review

**Activity:**
- Ball game (accessible to all, barcode-only)
- Returning students: quick EdBlocks refresh — open app, connect Edison, run a drive program
- New students: barcode exploration with returning students as mentors
- Class demonstration: line-following barcode vs. obstacle avoidance — what's the difference between these sensors?

**Materials:** Ball game setup, barcode list, devices, USB cables

---

### Session 2 — Follow the Line

**Opening concept:** A sensor program tells Edison to keep doing something until a condition changes.

**Physical activity:** PL-10 (Human Line Following with Sound Cues) — this is the main activity for the first 10–12 minutes. Two helpers with different noisemakers flank the blindfolded walker and cue corrections. Let students experience the left-right oscillation, then name it: "That weaving is not a bug — it's exactly what Edison will do. The sensor can only detect which side of the line it's on, not how centered it is." For new students who haven't done PL-7, run PL-7 for 3 minutes first so they understand the basic line-following idea before adding the sound cue complexity.

**Activity:**
- EdBlocks Activity 13: line-tracking sensor block
- Students draw their own line tracks on large paper (black marker on white)
- Program Edison to follow the line. Curves work better than sharp corners — why?
- Challenge: who can draw a line track that breaks Edison's line following? What causes it to fail?

**Engineering connection:** Finding the limits of a system is part of understanding it

**Materials:** Devices, USB cables, large white paper, thick black markers

---

### Session 3 — Stop at a Line

**Opening concept:** Sensors can trigger an action at exactly the right moment — but "exactly" is harder than it sounds.

**Physical activity:** PL-9 (Delay and Reaction Time) — tape a line on the floor, blindfolded student walks toward it, helper rings a bell on crossing, measure the overshoot. Run it at slow and fast speeds. Ask: "If Edison is driving fast and the sensor sees the line, what happens before the motors actually stop?" Then when Edison overshoots in the activity, students already know why.

**Activity:**
- EdBlocks Activity 14: sensor-triggered stop
- Build a "traffic system" — black tape lines across a course. Edison drives until it hits a line, stops.
- Teams design a two-lane course where Edisons take turns (human traffic controller starts each one)
- Challenge: can you program Edison to stop, wait 2 seconds, then continue? (combines drive + sensor + wait blocks)

**Engineering connection:** Sequential + event-driven programming combined

**Materials:** Devices, USB cables, black tape, large open floor space

---

### Session 4 — Lights and Sound

**Opening concept:** Output isn't just movement — robots can communicate through light and sound.

**Activity:**
- EdBlocks Activities 15–16: sound blocks (speaker output), LED light blocks
- Students program a "robot greeting" — Edison plays a sound and flashes lights when you press play
- Challenge: program a morse-code style message using lights (dot = short flash, dash = long flash). Teams decode each other's messages.

**Engineering connection:** Communication is a system requirement — how do you know your robot did what you wanted if it doesn't tell you?

**Materials:** Devices, USB cables, morse code reference sheet (simple version)

---

### Session 5 — Obstacle Detection

**Opening concept:** If Edison can sense an obstacle, it can decide what to do about it.

**Physical activity:** PL-6 (Obstacle Avoidance Rule) — brief revisit. This time, after the "always turn right" round, ask students to invent a better rule. Try a couple of their suggestions. Then: "Today we're going to program Edison with a rule. What rule should we give it?" Students come in already thinking about the design before they open EdBlocks.

**Activity:**
- EdBlocks Activities 17–18: obstacle sensor block, detect-and-avoid program
- Program Edison to drive until it detects an obstacle, then turn and continue
- Build a random obstacle field. Time how long Edison survives before getting stuck.
- Modify the turn direction or amount — does it survive longer?

**Engineering connection:** Tuning a parameter to improve performance, tracked with a timer as the metric

**Materials:** Devices, USB cables, cups/blocks for obstacles, timer

---

### Session 6 — Stay in Borders

**Opening concept:** Two sensors working together give a robot much more capability than either alone.

**Activity:**
- EdBlocks Activity 19: combined line + obstacle detection (stay in borders behavior, student-programmed version)
- Build a custom arena with black tape border. Program Edison to stay inside.
- Sumo 2.0: both robots programmed to stay in the arena. When one gets pushed to the border and drives out, the other wins.
- Bracket tournament: 4 or 6 robots, elimination rounds

**Engineering connection:** Combining subsystems — this is how real robots work

**Materials:** Devices, USB cables, large tape-bordered arena (tabloid paper with taped border works)

---

### Session 7 — Music and Performance

**Opening concept:** Engineers can choose to make something beautiful, not just functional.

**Activity:**
- EdBlocks Activities 20–21: musical note blocks, combining lights and music
- Students program a short performance: a melody + coordinated light pattern, ending with a drive move
- "Robot Talent Show" — each team presents their performance. Class votes for favorite.
- Bonus challenge: can you program the chorus of a real song? (Simple ones: Happy Birthday, Mary Had a Little Lamb)

**Engineering connection:** Creative coding — requirements are aesthetic, not just functional

**Materials:** Devices, USB cables, simple sheet music reference (note → EdBlocks note block mapping)

---

### Session 8 — Grand Challenge

**Opening concept:** Big challenges require combining everything you know.

**Activity:**
- Each team gets a "mission card" describing a course: e.g., "Drive to the ball, deliver it to the goal, then return to start and play a victory song"
- All programming done on devices, any EdBlocks features allowed
- 20 minutes to program, 10 minutes of runs, 10 minutes of debrief
- Debrief: what was the hardest part? What did you give up on and why?

**Engineering connection:** Real engineering involves tradeoffs and prioritization

**Materials:** Devices, USB cables, ball game setup, tape course, mission cards (teacher-prepared)

## Class 6 — Grade 4, Semester 2: "Robot Masters"

**Goal:** Students tackle open-ended design challenges using EdBlocks (advanced) or EdScratch. Emphasis on the full engineering process as a repeatable professional skill, not just a classroom activity. Capstone project is student-designed.

**Who's in the room:** Mix of returning Class 5 students and new-to-the-grade students. Session 1 accessible to all. New students may be at EdBlocks level while returning students use EdScratch — that's expected and fine.

**Programming level:** Level 4 (EdBlocks 16–23) for new-to-grade students; Level 5 (EdScratch Units 1–4) for returning students

**Key activities:** EdScratch loops + conditionals, geometry challenge, Operation: Neko Prime (if not done), capstone project

---

### Session 1 — Warm-Up and Placement

**Activity:**
- Ball game, barcode level (immediate access for all)
- Quick self-assessment: returning students open EdBlocks or EdScratch and build a simple drive program from memory. New students start with barcode exploration.
- Instructor circulates and places students into two tracks: EdBlocks (new/review) or EdScratch (continuing)
- Close: introduce capstone project concept — by Session 8, every team will present a working robot program that solves a problem they identified themselves

**Materials:** Ball game setup, barcode list, devices, USB cables

---

### Session 2 — EdScratch: Move It

**Activity:**
- EdBlocks track: Activities 17–19 (obstacle + border sensors)
- EdScratch track: Unit 2 (Move It) — driving, outputs, motor control in Scratch environment

- Compare approaches: how is EdScratch's code different from EdBlocks for the same task?

**Materials:** Devices, USB cables, EdScratch student sheets Unit 2, EdBlocks student sheets 17–19

### Session 3 — Loops and Geometry

**Opening concept:** A loop that runs 4 times with a drive + 90° turn should make a square. Does it?

**Activity:**
- EdBlocks track: Activity 20–21 (music + performance) combined into one session
- EdScratch track: Unit 3 (Got Loops?) — loop blocks, forever loops, nesting
- Shared challenge: program Edison to drive a rectangle using loops. Measure and verify.
- Extension: Quad Squad setup — can you program a triangle? A pentagon? What's the turn angle for each?

**Engineering connection:** Math predicts behavior. When it doesn't match, something is wrong and findable.

**Materials:** Devices, USB cables, EdScratch student sheets Unit 3, rulers, protractors, printed angle reference

---

### Session 4 — Quad Squad: Geometry Challenge

**Opening concept:** STEAM means the math and the engineering are the same problem.

**Activity:**
- Full Quad Squad lesson (from `curriculum/AdditionalActivities/Quad-Squad-robots.pdf`)
- Students program Edison to drive all four types of quadrilateral: square, rectangle, parallelogram, trapezoid
- Compare interior angles for each shape, calculate the exterior turn angle, program it, test it
- Debrief: which shape was hardest? Why? (Trapezoid — non-uniform turns)

**Engineering connection:** Understand before Build — write the turn angles down before programming them

**Materials:** Devices, USB cables, Quad Squad student sheets, protractors, rulers

---

### Session 5 — Conditionals and Line Algorithms

**Opening concept:** If-then logic lets a robot make decisions, not just follow a script.

**Activity:**
- EdScratch track: Unit 4 (What If...?) — conditionals, if statements, line-tracking algorithm
- EdBlocks track: Activity 13–14 revisited — design a program that stops at a specific line, flashes lights, then continues
- Shared challenge: program a traffic light intersection — Edison stops at red tape, goes on green (clap = green light)

**Engineering connection:** Event-driven programming. The robot waits for a condition, then responds.

**Materials:** Devices, USB cables, EdScratch Unit 4 sheets, red and green tape, barcode list

---

### Session 6 — Design Challenge: Course Builders

**Opening concept:** A good engineer defines the problem before touching any tools.

**Activity:**
- Teams design the hardest possible course they can, with constraints: must be completable by another team, must require at least two different programming techniques
- Write the course requirements on a card: what does "success" look like?
- Swap and attempt — 20 minutes to program for another team's course
- Score: partial credit for getting partway through

**Engineering connection:** Understand is engineering work. A vague Understand produces a broken Build.

**Materials:** Devices, USB cables, all course-building materials, index cards for requirements

---

### Session 7 — Capstone Project Work

**Activity:**
- Teams present their capstone problem statement (1 minute each): what problem are they solving, what does success look like, what's their plan?
- 40 minutes of build/test time with instructor circulating
- Must show at least 2 iterations — record what changed between version 1 and version 2

**Engineering connection:** Milestones. A capstone is a real project, not just a longer activity.

**Materials:** Devices, USB cables, any materials students need, paper for iteration log

### Session 8 — Capstone Showcase

**Opening concept:** Engineers communicate their work as clearly as they build it.

**Activity:**
- Each team gets 3 minutes to present: problem, solution, one thing that didn't work and how they fixed it, demo
- Audience asks one question per team
- Class vote: most creative, most reliable, hardest problem solved
- Closing debrief: what do robots still can't do that you wish they could?

**Materials:** All capstone projects, room setup for presentations

### Instructor Notes on Common Issues

**Edison won't scan a barcode.** Avoid glossy paper and direct sunlight. Press the record button exactly three times — not two, not four. If it still fails, try calibration barcodes from the complete barcode list.

**Edison drifts when driving straight.** Run drive calibration barcodes. This is also a great engineering teaching moment — explain why mechanical tolerances cause drift.

**EdBlocks won't connect.** Check USB cable (some cables are charge-only; you need data-capable). Try a different browser (Chrome works best). If on iPad, USB-to-Lightning or USB-C adapter must support data.

**Students get frustrated with the maze.** Remind them that finding a bug is progress. The robot didn't do something random — it did exactly what the program said. The program has a mistake we can find.

**Advanced students finish early.** Have a standing challenge ready: program the most complex thing you can. Pairs can also switch roles — the person who didn't type the last program has to explain what each block does.
